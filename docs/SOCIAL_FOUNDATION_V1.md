# أبو علي شات — Social Foundation v1
## الهدف
تحويل دليل المستخدمين المفتوح إلى شبكة علاقات آمنة، مع الحفاظ على الرسائل والوسائط الحالية وعدم تعديل الإنتاج قبل اختبار الترحيل.

## مبادئ لا تقبل التنازل
- الهوية تأتي حصراً من auth.uid() وليس من معرّف يرسله العميل.
- لا يحق لأي مستخدم قراءة الرسائل أو فتح محادثة خاصة أو بدء مكالمة إلا إذا كان الطرفان صديقين بحالة accepted، مع استثناءات انتقالية مدروسة للمحادثات القديمة بعد موافقة المالك.
- فرض القيود في PostgreSQL/RLS والدوال الآمنة، لا في الواجهة فقط.
- لا حذف أو تغيير للجداول الحالية قبل أخذ نسخة احتياطية ومراجعة مخطط قاعدة البيانات.
- الحظر يمنع البحث التفاعلي والطلبات والرسائل والمكالمات من الطرف المحظور.
- لا كشف لرقم الهاتف أو البريد أو جهات الاتصال في الملف العام.

## حالات العلاقة
none -> pending -> accepted
pending -> rejected / cancelled
accepted -> removed
any -> blocked (الحظر سجل مستقل)
يجب أن تكون العلاقة فريدة لكل زوج غير مرتب من المستخدمين، مع قيد UNIQUE على (least(user_a,user_b), greatest(user_a,user_b)) أو مفتاح زوج ثابت؛ المعاملات المتزامنة لا تعتمد على فحص من الواجهة.

## تجربة المستخدم
1. تبويب «اكتشف»: بحث بالاسم/اسم المستخدم، وأصدقاء مقترحون مع احترام إعدادات الخصوصية والحظر.
2. بطاقة المستخدم: صورة شخصية، غلاف، اسم، نبذة، أصدقاء مشتركون (إن سمحت الخصوصية)، زر إضافة صديق أو «تم الإرسال» أو «قبول/رفض» أو «مراسلة» حسب الحالة.
3. القائمة ⋮: حظر، إبلاغ، إزالة صداقة، مشاركة رابط الملف الشخصي.
4. تبويب «الأصدقاء»: الأصدقاء، الطلبات الواردة، الطلبات الصادرة، المقترحون.
5. رأس المحادثة: صورة واسم، زر اتصال صوتي وزر فيديو، مع حالة تعطيل مفسّرة إذا لم تتحقق شروط الاتصال.
6. ملفي الشخصي: رفع صورة وغلاف مع قصّ ومعاينة قبل الحفظ؛ الاسم والنبذة والخصوصية.
7. الإشعارات: طلب صداقة جديد، قبول طلب، رسالة من صديق، مكالمة فائتة.

## خصوصية
friend_request_policy = everyone | mutuals | nobody
profile_visibility = everyone | friends
last_seen_visibility = everyone | friends | nobody
read_receipts = boolean
لا يُسمح باقتراح حساب محظور أو مستخدم اختار عدم الظهور.

## الجداول/الترحيل (مبدئي — يجب مواءمته مع المخطط الفعلي)
profiles: user_id, display_name, username, avatar_path, cover_path, bio, privacy_settings
friendships: requester_id, addressee_id, status, created_at, responded_at, pair_key
blocks: blocker_id, blocked_id, created_at
notifications: recipient_id, actor_id, kind, entity_id, read_at, created_at
reports: reporter_id, reported_id, reason, created_at
calls: caller_id, callee_id, conversation_id, type, status, started_at, ended_at
Storage: avatars / covers مع صلاحيات رفع تخص المالك فقط، وفحص نوع الملف والحجم.

## العمليات الآمنة المطلوبة
send_friend_request(target): التحقق من الجلسة، الخصوصية، الحظر، منع الذات، التكرار، وتحديد معدل الطلبات.
respond_friend_request(request_id, decision): المستلم وحده يقرر القبول أو الرفض.
cancel_friend_request(request_id): المرسل وحده يلغي الطلب المعلق.
remove_friend(user_id): أحد طرفي العلاقة المقبولة فقط.
block_user(user_id): منع العلاقة والتفاعل وفق سياسة المنتج.
create_private_conversation(target): تحقق accepted + لا حظر + منع الذات + UNIQUE للزوج + معاملة ذرية.
send_message(conversation_id,...): تحقق العضوية والصداقة وعدم الحظر على مستوى قاعدة البيانات.

## مراحل الإنجاز والقبول
A. فحص مخطط البيانات والكود الحالي ونسخ احتياطية.
B. ترحيل العلاقات والخصوصية + RLS + اختبارات تزامن ورفض وصول غير مصرح.
C. الواجهة: ملفات شخصية، غلاف، بحث، مقترحون، طلبات، قبول ورفض، حظر وإبلاغ.
D. ربط الرسائل بحالة الصداقة دون فقد الرسائل القديمة.
E. WebRTC للمكالمات مع إشارات الاتصال والإذن بالميكروفون والكاميرا وSTUN/TURN وسجل المكالمات.
F. اختبارات حسابين وأجهزة مختلفة + قابلية الوصول + أداء + نشر تدريجي.

## الهوية البصرية
Royal Noir: خلفيات فحمية، درجات بنفسجي داكن، لمسات ذهبية محسوبة، أسطح زجاجية هادئة، خط عربي مقروء، حركة 150–220ms مع احترام prefers-reduced-motion، حالات تحميل وخطأ وفراغ، واجهة RTL متجاوبة.
## ملاحظة تنفيذية
هذا الملف يثبت التصميم الهندسي فقط. لم يتم تشغيل ترحيل أو تعديل قاعدة بيانات أو نشر إصدار جديد. لا يُعتبر أي بند مكتملًا قبل اختبار فعلي.
